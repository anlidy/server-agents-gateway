# v2：个人服务器 Hub

- **Version:** 2.0.0
- **Status:** 设计（未实现）
- **相对:** v1.0.0（零信任白名单控制面）
- **本文替代:** 不存在更早的 v2 草稿；实现以本文为准

v1 把网关写成「生产控制面」：命令白名单、fencing token、所有资产都按 RUNNING/STOPPED 对账。个人 Linux 服务器上通常只有同一个人的几个 Agent（手机、桌面 IDE、偶尔一台脚本机），要的是记下每次操作、有一份共享的服务器画像、误删能还原。真 shell 一开，MCP 上的白名单和强制锁都可以绕过，两套语义会把 Agent 搞懵。

v2 换轴，不换协议：仍是 MCP over SSE、per-agent Bearer、SQLite、零第三方依赖。改的是工具面、执行器、审计表、资产模型和删除路径。

## 1. 四层

| 层 | 职责 |
| :--- | :--- |
| 身份 | per-agent token。决定审计里的 `agent_id`，以及谁能签发凭据。不决定能跑什么命令。 |
| 共享记忆 | 资产 wiki + `SERVER_AGENTS.md`。不执行。 |
| 痕迹 | 每次工具调用都入库，可完整回放。 |
| 手 | 默认全开的 `bash -lc`；MCP 读/写/删文件。删除进回收站。 |

防出事靠完整日志和回收站，不靠拦截命令。

**自保（不是权限模型）：** `hub_write_file` / `hub_delete_file` / `rm` 包装器拒绝改动数据库文件、`.env`、`data/`。绝对路径 `/bin/rm` 仍可真删——接受这个缺口，避免包装器把账本烧掉。

**不做：** 持久 PTY、`LD_PRELOAD`、文件系统快照、`allowlist|open` 双模式、Postgres、多租户。每次 `hub_shell` 是新进程，不保留 cwd。

## 2. 相对 v1

| v1 | v2 |
| :--- | :--- |
| `hub_execute_command` 前缀白名单 + argv `shell=False` | `hub_shell`：`bash -lc`，管道和重定向可用 |
| 无读文件工具，白名单也没有 `cat` | `hub_read_file` |
| `hub_edit_file` 同目录 `.bak` | `hub_write_file`，覆盖先进回收站 |
| `hub_delete_file` 硬删 | 进回收站，可 restore，30 天过期 |
| `hub_manage_service` | 删除；`systemctl` / `docker` 走 shell |
| `lock_required` + fencing token | 可选 claim（贴纸）。MCP 写工具在他人未过期 claim 时 423；shell 不检查 |
| 审计 `output_summary` 截 400 字 | `audit_events` + `audit_bodies`，全文进 SQLite，合计 2MB 硬顶 |
| 资产 = 进程库存（desired/observed RUNNING） | 资产 = wiki + 可选 probe |
| `hub_cleanup_temp` | 删除；过期由回收站 purge |
| 旧工具名别名 | 不留。客户端重连走新的 `tools/list` |

保留：SSE/JSON-RPC、token 签发/吊销（仅 root admin）、WAL SQLite、密钥脱敏、LLM 编译 overview（换输入）。

## 3. 工具

原则：shell 负责干活；MCP 只保留 shell 给不了的语义（结构化读写、强制进回收站、改 wiki、查审计、管身份）。

| 工具 | 说明 |
| :--- | :--- |
| `hub_issue_agent_token` / `hub_revoke_agent_token` | 仅 root admin。在线签发一律 operator |
| `hub_shell` | `command` + `reason` 必填；可选 `cwd`、`timeout_seconds` |
| `hub_read_file` | `path`；可选 `offset`/`limit`。目录和二进制拒绝 |
| `hub_write_file` | `path` + `content` + `reason`。已存在则先回收旧文件 |
| `hub_delete_file` | 进回收站 |
| `hub_list_trash` / `hub_restore_file` | restore 按 `trash_id`；目标已存在则失败，不覆盖 |
| `hub_upsert_asset` / `hub_query_assets` | wiki 的写和读 |
| `hub_get_overview` / `hub_rebuild_overview` | 任何已认证 Agent 可 rebuild |
| `hub_claim` / `hub_release_claim` | 默认 TTL 1800s。自己再 claim 即续期 |
| `hub_query_audit_logs` | 只返回事件行，不含 stdout/stderr |
| `hub_get_audit_event` | 按 id 取事件 + body |
| `hub_get_status` | df/mem/load + 资产 observed 计数 + 未过期 claim |

删除：`hub_execute_command`、`hub_edit_file`、`hub_register_asset`、`hub_manage_service`、`hub_acquire_lock`、`hub_renew_lock`、`hub_release_lock`、`hub_cleanup_temp`。

Claim 生效范围：`hub_write_file` / `hub_delete_file`（路径落在该资产 `paths_json` 或其 `kind=path` 的 key 下）和 `hub_upsert_asset`。读与 `hub_shell` 不检查。

所有调用不论成败都写审计。改机器或改记忆的工具 `reason` 必填。

## 4. 执行

```python
subprocess.run(
    ["/bin/bash", "-lc", command],
    cwd=cwd, env=env, capture_output=True, text=True, timeout=timeout,
    start_new_session=True,
)
```

- 默认 cwd：`GATEWAY_SHELL_CWD`，否则 `$HOME`，否则 `/`。不要默认网关安装目录。
- 默认超时 120s，上限 3600s。超时 `killpg`，`exit_code=-1`，已有输出仍入库。
- `env` 继承进程环境，前置 `PATH=<gateway_root>/wrappers:$PATH`。不接受客户端传入的环境变量。
- 空命令拒绝；`command` 上限 64KB。

**`wrappers/rm`：** PATH 上的 Python 可执行文件（非交互 bash 不加载 alias）。解析 `-r/-f/-d/--`，每个操作数 `trash_put`。不支持的选项直接失败。注入 `SAG_AGENT_ID` 写入回收站。

逃生口只有绝对路径 `/bin/rm`、`/usr/bin/rm`。`command rm` 仍走 PATH。不包装 `mv`（改名不是删除）。不拦 `unlink`、`python os.remove`、`find -delete`——只记日志。

stdout+stderr 合计 2MB，先截 stdout 再截 stderr，MCP 响应与入库是同一份（含脱敏）。`finally` 里 reconcile。

## 5. 审计

个人服务器量级（每天几十到几百次调用）不值得上侧车文件。风险是 `SELECT *` 把正文拉爆，所以拆表，不是拆出文件系统。

```sql
CREATE TABLE audit_events (
    id TEXT PRIMARY KEY,
    timestamp TEXT NOT NULL,
    agent_id TEXT NOT NULL,
    tool_name TEXT NOT NULL,
    action_type TEXT NOT NULL,
    target TEXT NOT NULL,
    reason TEXT NOT NULL DEFAULT '',
    status TEXT NOT NULL,           -- SUCCESS | FAILED | REJECTED
    exit_code INTEGER,
    cwd TEXT,
    duration_ms INTEGER,
    params_json TEXT,
    trash_id TEXT,
    output_bytes INTEGER NOT NULL DEFAULT 0,
    truncated INTEGER NOT NULL DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE audit_bodies (
    event_id TEXT PRIMARY KEY REFERENCES audit_events(id) ON DELETE CASCADE,
    stdout TEXT,
    stderr TEXT,
    diff TEXT
);
```

- `SUCCESS`：做成了；`FAILED`：执行了但没做成（非零退出、不存在、超时）；`REJECTED`：没执行（自保、claim、非 admin）。
- 写入前走现有 `audit_redact`。签发工具的 token 明文不入库。
- `diff` 单独上限 64KB（旧文件在回收站）。
- 列表默认 limit 20、最大 200。`keyword` 只搜 `reason` 和 `params_json`。不加 FTS。
- 审计不自动删。回收站过期不级联删事件。

v1 `gateway_audit_logs` 迁入后改名为 `gateway_audit_logs_v1`。`intent_reason` → `reason`，`output_summary` → `stdout`。`tool_name` 按 `action_type` 映射（`shell_exec`→`hub_shell`，`file_modify`→`hub_write_file`，锁相关→`hub_claim`，其余见实现）。`lease_token` / `is_temporary` 丢弃。

## 6. 资产

一条资产是带结构的 wiki，不是 k8s desired state。没有 probe 的条目 `observed='n/a'`，禁止再写成 UNKNOWN 却 IN_SYNC。

```sql
CREATE TABLE gateway_assets (
    key TEXT PRIMARY KEY,
    kind TEXT NOT NULL,
    title TEXT NOT NULL,
    summary TEXT NOT NULL DEFAULT '',
    notes_md TEXT NOT NULL DEFAULT '',
    listen_json TEXT NOT NULL DEFAULT '[]',
    urls_json TEXT NOT NULL DEFAULT '[]',
    paths_json TEXT NOT NULL DEFAULT '[]',
    unit_name TEXT,
    depends_on_json TEXT NOT NULL DEFAULT '[]',
    probe_type TEXT NOT NULL DEFAULT 'none',
    probe_spec TEXT,
    want_up INTEGER,                -- 1 希望在跑, 0 故意停, NULL 不对账
    observed TEXT NOT NULL DEFAULT 'n/a',  -- up | down | unknown | n/a
    observed_at TEXT,
    claimed_by TEXT,
    claimed_until INTEGER,
    tags_json TEXT NOT NULL DEFAULT '[]',
    created_by TEXT,
    updated_by TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);
```

`kind` 是约定不是关死枚举：`host` / `systemd` / `docker` / `site` / `domain` / `path` / `repo` / `config` / `note`。未知 kind 仍可插入。key 建议 `kind:name`；**迁移时不改已有 key**。

| probe_type | up 的条件 |
| :--- | :--- |
| `none` | 不探 |
| `systemd` | `systemctl is-active` == `active` |
| `docker` | `docker ps -a` 状态以 `Up` 开头 |
| `http` | URL 返回 2xx/3xx，超时 3s |
| `tcp` | `host:port` connect 3s |

探失败（命令异常）写成 `unknown`，不要假装 `down`。`want_up=1 AND observed=down` 现算「漂了」，不存 `drift_status`。对账器不自动拉起。周期沿用 `RECONCILE_INTERVAL_SECONDS`，以及 shell/写删的 `finally`。

`listen_json` 是进程监听；`urls_json` 是访问 URL。v1 的 `endpoints_json` 里以 `http` 开头的进 urls，其余进 listen。

Overview 输入改为 title/summary/notes/depends/observed/claim + 最近 20 条事件（无 body）。落盘 `<gateway_root>/SERVER_AGENTS.md`。

v1 资产列：`category=web_app` → `kind=site`；其它 category → kind；`name` → title 且填 `unit_name`；`description` → summary；`config_paths_json` → `paths_json`；RUNNING/STOPPED/UNKNOWN → up/down/unknown；docker/systemd 设 `probe_type` 对应值且 `want_up=1`。`lock_required` / `desired_state` / `drift_status` 丢弃。旧表改名为 `gateway_assets_v1`。

## 7. 回收站

```
<data_dir>/trash/<id>/meta.json
<data_dir>/trash/<id>/payload    # 文件，或目录
```

| 动作 | 进回收站 |
| :--- | :--- |
| `hub_delete_file` | 是 |
| `hub_write_file` 覆盖 | 是（旧内容） |
| wrappers/`rm` | 是 |
| 新建文件、`/bin/rm`、purge | 否 |

`os.rename` 到 `payload`；`EXDEV` 则 copy 再删源。不用 tar。同一路径多次删除是多条历史；restore 只按 id。目标已存在则失败。restore 是取回（搬走 trash 条目），不是复制。

`expires_at = now + 30d`。对账周期末 purge 过期项。不提供清空工具。配置 `GATEWAY_TRASH_RETENTION_DAYS`。
